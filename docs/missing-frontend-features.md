# 前端 UI 待开发功能清单

> 以下 16 个后端 API 已实现但缺少前端 UI 入口。按功能模块分类，供设计者规划后续任务。

---

## 一、自定义命令系统（4 个 API）

后端已完整实现自定义命令的 CRUD + 执行。可理解为"系统快捷操作"——管理员预设一些常用操作（如：批量关闭过期攻关单、导出周报、发送提醒），用户在 UI 中一键触发。

| 方法   | 路径                | 功能说明                                                             |
| ------ | ------------------- | -------------------------------------------------------------------- |
| GET    | `/commands`         | 获取所有自定义命令列表。返回每个命令的名称、描述、脚本内容、创建时间 |
| POST   | `/commands`         | 创建新命令。需要提供名称、描述、脚本内容（JS 代码片段或 API 调用链） |
| DELETE | `/commands/:id`     | 删除指定命令                                                         |
| POST   | `/commands/:id/run` | 立即执行指定命令，返回执行结果（成功/失败/输出日志）                 |

**建议 UI 设计**：在系统管理菜单下新增"自定义命令"页面，类似"自动化规则"的概念。列表展示已有命令，支持新建/编辑/删除/手动执行。执行历史可作为后续扩展。

---

## 二、UI 置顶缓存 / 快捷访问（4 个 API）

用户可以将常用的节点（攻关单、人员、信息卡等）"置顶"到导航栏的快捷区域，类似于浏览器的书签栏。

| 方法   | 路径                   | 功能说明                                                    |
| ------ | ---------------------- | ----------------------------------------------------------- |
| POST   | `/ui-cache/pin`        | 置顶一个节点。body: `{ nodeId, nodeType, label, icon? }`    |
| GET    | `/ui-cache/pinned`     | 获取当前用户已置顶的所有项目。返回节点 ID、类型、标签、排序 |
| PATCH  | `/ui-cache/pinned/:id` | 更新置顶项（修改标签、图标、排序位置）                      |
| DELETE | `/ui-cache/pinned/:id` | 取消置顶                                                    |

**建议 UI 设计**：在侧边栏顶部或页面顶部增加"快捷访问"区域，显示置顶的节点卡片。在节点详情页增加"置顶/取消置顶"按钮。支持拖拽排序。

---

## 三、手动关系管理（3 个 API）

当前系统通过 AI 自动提议关系（proposals），用户审批。手动关系管理是更底层的能力——管理员可以直接创建/删除任意两个节点之间的关联，不需要经过提议-审批流程。

| 方法   | 路径                        | 功能说明                                                            |
| ------ | --------------------------- | ------------------------------------------------------------------- |
| POST   | `/relations/manual`         | 手动创建关系。body: `{ sourceId, targetId, edgeType, properties? }` |
| GET    | `/relations/manual`         | 获取所有手动创建的关系列表                                          |
| DELETE | `/relations/manual/:edgeId` | 删除指定的手动关系                                                  |

**建议 UI 设计**：在知识图谱页面或节点详情页增加"手动关联"模式。管理员可以拖拽连线或通过搜索选择目标节点来创建关系。手动关系用虚线或不同颜色与自动提议关系区分。

---

## 四、值班管理（1 个 API）

查询当前值班人员信息。可结合轮值规则，在首页或仪表盘显示"今日值班"。

| 方法 | 路径              | 功能说明                                     |
| ---- | ----------------- | -------------------------------------------- |
| GET  | `/oncall/current` | 返回当前值班人员（姓名、联系方式、值班时段） |

**建议 UI 设计**：在首页 Dashboard 顶部增加"今日值班"卡片。系统管理下增加"值班表"配置页面（需要配套后端排班 API）。

---

## 五、责任图谱可视化（1 个 API）

获取某个攻关单的完整责任链数据——从客户 → 攻关组长 → 处理人 → 协作者，以有向图的形式展示。

| 方法 | 路径                      | 功能说明                                                                       |
| ---- | ------------------------- | ------------------------------------------------------------------------------ |
| GET  | `/responsibility/diagram` | 返回责任图谱数据。包含节点（人员/组织）和边（汇报/协作关系），前端用图形库渲染 |

**建议 UI 设计**：在攻关单详情页增加"责任图谱"Tab，用 D3.js / G6 / ReactFlow 等图形库渲染力导向图或组织架构图。节点可点击跳转到对应人员/攻关单。

---

## 六、异地备份（1 个 API）

当前备份页面只支持本地文件备份。此 API 支持将备份文件推送到远程存储（S3/OSS/SCP）。

| 方法 | 路径              | 功能说明                                                                        |
| ---- | ----------------- | ------------------------------------------------------------------------------- |
| POST | `/backup/offsite` | 执行异地备份。读取系统配置中的远程存储信息，推送当前 SQLite 文件或 pg_dump 结果 |

**建议 UI 设计**：在备份管理页面增加"异地备份"按钮或自动定时备份配置。需要配套的远程存储配置 UI（endpoint、access key、bucket 等）。

---

## 七、文档下载入口（1 个 API）

Welink 集成的文档已支持上传和列表展示，但缺少独立的下载入口（当前只在 Welink 内嵌时使用）。

| 方法 | 路径                      | 功能说明                                                    |
| ---- | ------------------------- | ----------------------------------------------------------- |
| GET  | `/documents/:id/download` | 下载指定文档。返回文件流（Content-Disposition: attachment） |

**建议 UI 设计**：在文档列表的每行增加"下载"按钮（下载图标）。已上传文档的详情页也应有下载按钮。

---

## 八、支撑模板删除（1 个 API）

支撑模板当前只能创建和应用到攻关单，缺少删除功能。

| 方法   | 路径                             | 功能说明                                                     |
| ------ | -------------------------------- | ------------------------------------------------------------ |
| DELETE | `/support-templates/:templateId` | 删除指定支撑模板。如果模板已被某个攻关单引用，需提示用户确认 |

**建议 UI 设计**：在支撑模板列表中每行增加"删除"按钮，点击后弹出确认对话框。如果模板已应用到攻关单，提示"该模板已被 N 个攻关单使用，删除后不影响已应用的数据，确认删除？"

## 优先级建议

| 优先级  | 功能                    | 理由                                   |
| ------- | ----------------------- | -------------------------------------- |
| P0 高   | 文档下载 / 支撑模板删除 | 改动极小（1个按钮），用户立刻感知      |
| P1 中   | 手动关系管理            | 知识图谱核心交互，当前只能通过 AI 提议 |
| P1 中   | UI 置顶缓存             | 提升高频操作效率，用户体验提升明显     |
| P2 低   | 自定义命令              | 高级功能，管理员专用，可后续迭代       |
| P2 低   | 值班管理 / 责任图谱     | 需要配套后端排班 API 或前端图形库引入  |
| P3 规划 | 异地备份                | 运维功能，需要远程存储配置 UI          |
